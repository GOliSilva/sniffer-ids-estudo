# Módulo 04: O ev (2): o que se pede

=== ideia: As 6 propriedades do pedido

:::chave
Seis propriedades dizem **o que** a mensagem pede ou entrega: `operacao`, `funcao`, `area`, `endereco`, `quantidade` e `valores`. É aqui que mora quase todo ataque de payload.
:::

Na tela do Wireshark, elas estão na seção **Modbus** (a de baixo; a de cima, **Modbus/TCP**, é o cabeçalho, do módulo 05) ou, no S7, em **Parameter** e **Data**.

![A pergunta Modbus da linha de base no Wireshark: a seção Modbus aberta mostra a função e o Reference Number, que viram ev.funcao e ev.endereco](img/ws_modbus_endereco.png)

=== ideia: ev.funcao

:::termo{nome="ev.funcao"}
O **código da função** pedida, como está no protocolo.
- **Tipo** número inteiro (o sensor mostra em hexadecimal: `f=0x03`)
- **Modbus** o byte logo depois do cabeçalho MBAP (`modbus.func_code`)
- **S7** o primeiro byte dos parâmetros (`s7comm.param.func`)
- **Na linha de base** Modbus 3; S7 4 (`0x04`)
:::

| Código | Protocolo | O que é |
|---|---|---|
| 3 | Modbus | Read Holding Registers (ler) |
| 4 | Modbus | Read Input Registers (ler) |
| 6 | Modbus | Write Single Register (escrever um) |
| 16 (`0x10`) | Modbus | Write Multiple Registers (escrever vários) |
| 43 (`0x2B`) | Modbus | Encapsulated Interface Transport; com MEI 14, *Read Device Identification* |
| `0x04` | S7 | Read Var |
| `0x05` | S7 | Write Var |
| `0x28` / `0x29` | S7 | PLC Start / PLC Stop |
| `0xF0` | S7 | Setup Communication (o início de toda sessão S7) |

> **Erro comum:** procurar a exceção em `ev.funcao`. Numa resposta de erro, o Modbus manda a função **+ 0x80** (3 vira `0x83`), mas o sensor **tira** o `0x80`: `ev.funcao` continua 3 e o erro vai para `ev.status` (módulo 05).

=== ideia: ev.operacao

:::termo{nome="ev.operacao"}
A **tradução** de `funcao` numa palavra, feita pelo sensor.
- **Valores** `"leitura"`, `"escrita"`, `"controle"`, `"outra"`
- **Modbus** 1, 2, 3, 4 viram leitura; 5, 6, 15, 16 viram escrita; o resto vira outra
- **S7** `0x04` leitura; `0x05` escrita; `0x28` e `0x29` controle; o resto (inclusive Setup `0xF0`) outra
- **Na linha de base** só `"leitura"`
:::

Use `operacao` quando o tipo de pedido basta; use `funcao` quando precisa do código exato.

```python
ev.direcao == "pergunta" and ev.operacao == "escrita"          # qualquer escrita
ev.protocolo == "modbus" and ev.operacao == "outra"            # função que a planta não usa
ev.funcao == 16                                               # só escrita múltipla
```

> **Atenção:** o Setup Communication (`0xF0`) é `"outra"`. Toda sessão S7 nova começa com ele, então uma regra `operacao == "outra"` no S7 dispara em **qualquer** conexão nova, inclusive a reconexão legítima do GET.

=== ideia: ev.area

:::termo{nome="ev.area"}
**Que memória** do CLP está sendo acessada.
- **Tipo** texto
- **Modbus** vem da função: `"holding"` (3, 6, 16), `"input"` (4), `"coil"` (1, 5, 15), `"discreta"` (2); função desconhecida deixa `""`
- **S7** vem do item: `"DB1"` (área `0x84` + número do DB), `"M"` (marcadores, `0x83`), `"I"` (entradas), `"Q"` (saídas)
- **Na linha de base** Modbus `"holding"`; S7 `"DB1"`
:::

No Wireshark, no S7, a área é o campo *Area* e o DB é *DB number*, dentro de **Parameter > Item [1]**:

![A pergunta S7 da linha de base: Item [1] aberto, com a área DB, o DB number 1, o endereço e a quantidade de bytes](img/ws_s7_pergunta.png)

```python
ev.protocolo == "s7" and ev.area != "DB1"        # S7 em outra memória que não o DB1
```

=== ideia: ev.endereco e ev.quantidade

:::termo{nome="ev.endereco"}
**Onde** começa o acesso.
- **Modbus** o número do primeiro registrador (*Reference Number*, `modbus.reference_num`). HR0 é 0, HR2 é 2
- **S7** o **byte** dentro da área. No pacote o endereço vem em **bits**; o sensor divide por 8
- **Na resposta** a resposta não repete o endereço: o sensor **copia** da pergunta casada. Sem pergunta casada, fica 0
- **Na linha de base** 0
:::

:::termo{nome="ev.quantidade"}
**Quanto** se pede a partir do endereço.
- **Modbus** número de registradores (*Word Count*). Na escrita simples (função 6), vale 1
- **S7** número de elementos do item: aqui, **bytes**
- **Na linha de base** Modbus 10; S7 20
:::

Os dois juntos dizem a faixa acessada: de `endereco` até `endereco + quantidade - 1`. Para saber se uma leitura **sai do mapa** (HR0 a HR9):

```python
ev.protocolo == "modbus" and ev.direcao == "pergunta" and ev.endereco + ev.quantidade > 10
```

> **Erro comum:** testar só `ev.endereco > 9`. Uma leitura de HR5 com quantidade 10 vai até HR14 e passa nesse teste, mas sai do mapa.

=== ideia: ev.valores

:::termo{nome="ev.valores"}
Os **números** que a mensagem carrega, em grupos de 16 bits.
- **Tipo** lista de inteiros, de 0 a 65535
- **Resposta de leitura Modbus** todos os registradores lidos: `[252, 1, 0, 0, 0, 0, 0, 0, 0, 0]`. `valores[0]` é o do `endereco`
- **Pergunta de escrita Modbus** o valor escrito: função 6 dá `[300]`; função 16 dá todos os escritos
- **S7** na resposta de Read Var, os dados lidos de 2 em 2 bytes (`[82, 0, ...]`); na pergunta de Write Var, os dados escritos
- **Vazia** (`[]`) na pergunta de leitura, na resposta de escrita e nas respostas de erro
:::

![A resposta Modbus da linha de base: cada Register é um número de ev.valores](img/ws_modbus_resposta.png)

```python
ev.direcao == "resposta" and ev.valores and ev.valores[0] > 400     # HR0 fora da faixa
any(v > 400 for v in ev.valores)                                    # algum valor acima de 400
```

> **Erro comum:** escrever `ev.valores[0]` sem conferir que a lista tem algo. Numa pergunta de leitura, `valores` é `[]`, e `[][0]` dá erro (`IndexError`) e derruba o sensor. Comece com `ev.valores and ...`.

> **Atenção:** `valores[0]` é o registrador do `endereco`, não sempre o HR0. Numa leitura que começa em HR2, `valores[0]` é o HR2. Na linha de base o endereço é 0, então `valores[i]` é o HR*i*.

=== questao: Questão: o setpoint

### ✍️ Questão de prova Treino M04 Q1: escrita fora da faixa

O HR2 é o setpoint × 10 e só pode ir de 0 a 400. Escreva a regra que dispara quando alguém **pede** para escrever no HR2 um valor fora dessa faixa, com função 6 **ou** 16.

=== resolucao: Resolução

?? Qual ev olhar: a pergunta ou a resposta?

A **pergunta**. É nela que está o valor pedido (`valores`). A resposta de escrita não traz `valores`.

?? Como reconhecer uma escrita no HR2?

`ev.operacao == "escrita"` cobre as funções 6 e 16. O alvo é `ev.endereco == 2`.

?? E o valor?

Na função 6, `valores` tem um número; na 16, pode ter vários. `any(v > 400 for v in ev.valores)` funciona nos dois casos. (Como `valores` é sem sinal, não existe valor abaixo de 0.)

?? Como fica?

```python
def setpoint_fora(ev):
    return (ev.protocolo == "modbus" and ev.direcao == "pergunta"
            and ev.operacao == "escrita" and ev.endereco == 2
            and any(v > 400 for v in ev.valores))
```

> **Erro comum:** com a função 16, uma escrita que começa em HR1 com 2 registradores também atinge o HR2, e `ev.endereco` vale 1. Para ser completo, o HR2 é `ev.valores[2 - ev.endereco]` quando `ev.endereco <= 2 < ev.endereco + ev.quantidade`.

=== treino: Treino M04 Q2

### ✍️ Questão de prova Treino M04 Q2: qual propriedade?

Para cada fato, diga que propriedade do `ev` mostra:

1. Alguém pediu PLC Stop.
2. A leitura foi no DB2 em vez do DB1.
3. A resposta trouxe a temperatura 32767.
4. Alguém leu 125 registradores de uma vez.

??? resposta

1. `ev.operacao == "controle"` (ou `ev.funcao == 0x29`).
2. `ev.area == "DB2"`.
3. `ev.valores[0] == 32767` na **resposta** da leitura que começa em HR0.
4. `ev.quantidade == 125` na **pergunta**.

=== treino: Treino M04 Q3

### ✍️ Questão de prova Treino M04 Q3: o erro da regra

Esta regra derruba o sensor na linha de base. Por quê?

```python
def temperatura_alta(ev):
    return ev.protocolo == "modbus" and ev.valores[0] > 300
```

??? resposta

Na **pergunta** de leitura, `ev.valores` é `[]`, e `ev.valores[0]` dá `IndexError`. Corrija olhando só a resposta e conferindo a lista: `ev.direcao == "resposta" and ev.valores and ev.valores[0] > 300`.

=== resumo: Para levar

1. **ev.funcao:** o código cru (Modbus 3, 6, 16, 43; S7 `0x04`, `0x05`, `0x29`, `0xF0`). A exceção **não** fica aqui.
2. **ev.operacao:** leitura, escrita, controle ou outra. Setup S7 é "outra".
3. **ev.area:** `"holding"` no Modbus; `"DB1"`, `"M"`, `"I"`, `"Q"` no S7.
4. **ev.endereco + ev.quantidade:** a faixa acessada. A resposta copia o endereço da pergunta.
5. **ev.valores:** os números de 16 bits; `[]` na pergunta de leitura. Teste `ev.valores and ...` antes de indexar.
