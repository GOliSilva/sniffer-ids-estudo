# Módulo 07: Investigar no Wireshark e classificar

=== ideia: O método em seis passos

:::chave
Quem recebe um pcap sem contexto **não sai procurando o ataque**. Compara com a linha de base e vai **do resumo ao quadro**, sempre na mesma ordem.
:::

| Passo | Onde, no Wireshark | Na linha de base |
|---|---|---|
| 1. Inventário | *Statistics > Capture File Properties*, *Protocol Hierarchy*, *Endpoints*, *Conversations* | 542 quadros; 3 IPs; 2 conversas TCP de 270 quadros; 2 ARP |
| 2. Saúde do TCP | *Analyze > Expert Information*; `tcp.analysis.flags`; `tcp.flags.syn==1 \|\| tcp.flags.fin==1 \|\| tcp.flags.reset==1` | nada |
| 3. Saúde da aplicação | `modbus.exception_code`; `s7comm.header.errcls != 0`; `s7comm.header.rosctr==3 && s7comm.data.returncode != 0xff` | nada |
| 4. O que se pede | `modbus.func_code != 3`; `s7comm.param.func != 0x04`; `mbtcp.unit_id != 1`; `mbtcp.prot_id != 0` | nada |
| 5. Tempo | *Statistics > I/O Graphs*; `modbus.response_time` | linhas planas; Modbus de 3 a 7 ms |
| 6. Quadro | *Analyze > Follow > TCP Stream*; abrir o quadro; *Apply as Column* nos valores | |

A ordem importa: cada passo que **não acha nada** também é anotado, porque descarta hipóteses. Quem pula direto para um filtro específico só acha o que já esperava achar.

> **Atenção:** deixe a linha de base aberta numa **segunda janela** do Wireshark. Um número só diz algo quando comparado.

=== ideia: Passo 2: Expert Information

:::chave
O Expert Information junta tudo que o Wireshark acha estranho: retransmissão, conexão aberta ou fechada, campo inválido.
:::

![Analyze > Expert Information no caso 6 da aula: as retransmissões do CLP A, que pergunta ao CLP B e não recebe nem ACK](img/ws_expert.png)

Na linha de base ele fica **vazio**. Tudo que aparecer é diferença.

| Aviso | O que indica |
|---|---|
| *suspected retransmission* | o outro lado não confirmou: rede ou equipamento fora |
| *Connection establish request (SYN)* | uma conexão nova |
| *Connection finish (FIN)* | alguém fechou a conversa, de forma ordenada |
| *Invalid protocol ID* (Modbus) | Protocol ID diferente de 0 |

=== ideia: Pegadinhas do Wireshark

- `modbus.func_code` **não** guarda o bit de exceção: `modbus.func_code > 0x80` não acha nada. Use `modbus.exception_code`.
- `s7comm.data.returncode` existe também no **pedido** de Write Var (vale `0x00`). Por isso o filtro de erro do item fica só nas respostas: `s7comm.header.rosctr==3 && ...`.
- `modbus.response_time` só existe quando **há** resposta. Ele não acha timeout.
- `tcp.srcport==502 && tcp.len==0` pega também FIN e SYN+ACK. Para só o ACK puro: `tcp.flags==0x010`.
- `!modbus.request_frame` numa resposta = o Wireshark **não achou** a pergunta dela.

=== ideia: Do Wireshark ao ev

:::chave
Cada campo que você acha no Wireshark tem um par no `ev`. É essa tabela que transforma o achado em regra.
:::

| Campo no Wireshark | No `ev` |
|---|---|
| `ip.src`, `ip.dst` | `origem`, `destino` |
| `tcp.srcport`, `tcp.dstport` | `porta_origem`, `porta_destino` |
| `mbtcp.trans_id`, `s7comm.header.pduref` | `transacao` |
| `mbtcp.prot_id` | `id_protocolo` |
| `mbtcp.len`, `tpkt.length` | `tamanho` |
| `mbtcp.unit_id` | `unidade` |
| `modbus.func_code`, `s7comm.param.func` | `funcao` (e `operacao`) |
| `modbus.reference_num` | `endereco` |
| `modbus.word_cnt`, `s7comm.param.item.length` | `quantidade` |
| `s7comm.param.item.db`, `s7comm.param.item.area` | `area` |
| `modbus.regval_uint16`, dados do item S7 | `valores` |
| `modbus.exception_code`, `s7comm.header.errcls/errcod`, `s7comm.data.returncode` | `status` |
| `modbus.request_frame` existe | `pareada` |
| `modbus.response_time` | `tempo_resposta` |
| o painel de bytes do payload | `bruto` |

**Sem par no `ev`:** MAC, ARP, flags TCP (SYN, FIN, RST), retransmissão como tal. Isso se prova no Wireshark e, quando precisa de regra, se pega pelo **efeito** (regra com memória).

=== ideia: Classificar

:::chave
**Quem**, **quantas vezes** e **quando** separam falha, configuração e ataque.
:::

| Sinal | Puxa para |
|---|---|
| IP ou MAC fora do inventário | fora da política |
| desde o primeiro segundo, igual até o fim | configuração (falha) |
| começa no meio, de repente | evento: falha ou ataque |
| sempre o mesmo pedido, no ritmo da planta | o programa de sempre, configurado errado |
| pedido mudando a cada vez (endereços, Unit IDs, funções) | sondagem: fora da política |
| uma tentativa, recusada | sondagem: fora da política |
| retransmissão, SYN sem resposta, ARP sem resposta | falha de rede (enlace ou transporte) |
| ACK do TCP presente, resposta da aplicação ausente | falha da aplicação |
| quem pode, fazendo o que pode, dentro da faixa | diferente, mas permitido |

Hábitos do ofício:

- Anote **tempo e número do quadro** de cada achado. Ponha os achados em ordem: a causa vem antes do sintoma.
- A captura prova o que **passou pelo fio**. Pacote enviado prova **tentativa**; efeito pede um valor lido depois.
- Escreva cada hipótese descartada junto com o quadro que a descartou.

=== questao: Questão: em que passo aparece?

### ✍️ Questão de prova Treino M07 Q1: o passo certo

Em que passo do método cada diferença aparece primeiro?

1. Um IP novo falou com o CLP B.
2. Uma resposta Modbus voltou com exceção 02.
3. A resposta Modbus passou a demorar 400 ms.
4. Uma pergunta Modbus com Unit ID 7.

=== resolucao: Resolução

?? O que cada passo olha?

1 inventário (quem e quanto); 2 TCP; 3 erros da aplicação; 4 o que se pede; 5 o tempo; 6 o quadro.

?? Encaixando:

1. **Passo 1**: Endpoints mostra um IP a mais.
2. **Passo 3**: `modbus.exception_code`.
3. **Passo 5**: `modbus.response_time`. Os passos 1 a 4 não acham nada: mesmo número de quadros, nenhum erro, nenhum pedido diferente.
4. **Passo 4**: `mbtcp.unit_id != 1`.

> **Erro comum:** parar no passo 2 e dizer "normal". Uma diferença só de tempo ou só de um campo do cabeçalho passa limpa pelos passos 1, 2 e 3.

=== treino: Treino M07 Q2

### ✍️ Questão de prova Treino M07 Q2: do campo à regra

No Wireshark você achou `s7comm.param.item.db == 2` nos pedidos do quadro 4 em diante. Que propriedade do `ev` usa, e como fica a condição?

??? resposta

`ev.area`, que no S7 junta a área e o número do DB: `"DB2"`. Condição: `ev.protocolo == "s7" and ev.direcao == "pergunta" and ev.area == "DB2"`. A resposta casada também traz `area == "DB2"`, copiada da pergunta.

=== treino: Treino M07 Q3

### ✍️ Questão de prova Treino M07 Q3: classifique pelo padrão

O CLP A pede o DB2 do CLP B uma vez por segundo, **do primeiro ao último quadro**, sempre pela porta 2001, e toda resposta volta com o item `0x0A`. Classifique e diga qual das três perguntas decidiu.

??? resposta

**Falha de comunicação, aplicação: configuração** (o GET do CLP A aponta para um DB que não existe). Decidiram o **quem** (o próprio CLP A, na conexão de sempre) e o **quando** (desde o início, igual até o fim: não é evento). É o caso 7 da aula.

=== resumo: Para levar

1. **Seis passos:** inventário, TCP, aplicação, o que se pede, tempo, quadro. Anote até o que não achou nada.
2. **Endpoints, Conversations, Protocol Hierarchy:** quem apareceu ou sumiu.
3. **Expert Information:** vazio na base; tudo que aparece é diferença.
4. **I/O Graph:** quando começou. Igual do início ao fim = configuração.
5. **Cada campo do Wireshark tem par no `ev`**, menos MAC, ARP e flags TCP.
6. **Classificar:** quem, quantas vezes, quando.
