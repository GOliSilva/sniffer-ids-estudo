# Roteiro

=== ideia: Como é a prova

:::chave
Você recebe a **linha de base** e **10 capturas**. Para cada captura, escreve no `regras.py` **uma regra** que dispara **só nela**, diz o que aconteceu e prova com o quadro do Wireshark.
:::

O que chega no computador da prova:

| Arquivo | O que é |
|---|---|
| `linha_de_base.pcap` | a planta funcionando normal: o retrato com que tudo se compara |
| `caso_01.pcap` a `caso_10.pcap` | a mesma planta, cada uma com **uma diferença** |
| `captura.py`, `protocolos.py`, `sensor.py` | o sensor pronto: lê o pcap e transforma cada mensagem num `ev` |
| `regras.py` | o inventário, o `avaliar()`, a `Janela` e o `comparar()` prontos, e a lista **`REGRAS` vazia** |

O trabalho, para cada caso:

1. **Achar a diferença** em relação à linha de base. Vale usar o **Wireshark** e o próprio sensor.
2. **Escrever a regra**: uma função que recebe o `ev` e devolve `True` quando ele é o problema. Ela entra na lista `REGRAS`.
3. **Conferir a precisão**: a regra dispara no caso dela e em **nenhum outro**, nem na linha de base.
4. **Classificar**: falha de comunicação, fora da política (ataque) ou diferente, mas permitido.
5. **Provar**: o quadro, o campo e o valor que mostram o problema.

> **Atenção:** alguns casos da prova repetem os tipos vistos na aula de diagnóstico, e outros são **novos**. Por isso o site treina o **método**, não uma lista de respostas.

=== ideia: Baixe a pasta de treino

:::chave
A pasta tem o **sensor da prova**, o `regras.py` vazio, o **checador** e as capturas do **simulado** e da **aula**.
:::

[Baixar a pasta de treino (simulado_sniffer.zip)](downloads/simulado_sniffer.zip)

Na pasta:

```
captura.py  protocolos.py  regras.py  sensor.py   o sensor da prova
conferir.py                                      o checador
capturas/          linha_de_base.pcap e caso_01 a caso_10 (simulado)
capturas_aula/     linha_de_base.pcap e caso_01 a caso_10 (aula de diagnóstico)
LEIAME.txt
```

Preparação, uma vez só, no terminal dentro da pasta:

```
python -m venv .venv
.venv\Scripts\activate
pip install scapy
```

Rodar o sensor numa captura e o checador em todas:

```
python sensor.py --arquivo capturas\caso_01.pcap
python conferir.py
python conferir.py --pasta capturas_aula
```

> **Atenção:** o `protocolos.py` da prova é o da aula de diagnóstico **com campos a mais** no `ev` (Unit ID, transação, tamanho, bytes brutos e outros). Use esta pasta para treinar, não a da aula.

=== ideia: Como usar o site

Cada módulo é uma sequência de **cartões**. Passe com os botões, deslizando para o lado ou com as setas do teclado.

1. **Ideias:** a teoria, um conceito por cartão.
2. **Questão:** um problema no estilo da prova.
3. **Resolução:** revelada passo a passo. Antes de cada passo há uma pergunta para você pensar.
4. **Treino:** problemas parecidos, um por cartão. Abra a resposta e marque se acertou.
5. **Resumo:** o que levar para a prova.

No topo, **Treino** esconde as respostas e **Revisão** deixa tudo aberto. O site lembra o cartão em que você parou.

=== ideia: As cores

O negrito curto ganha a cor do assunto. As figuras usam as mesmas cores.

- **Modbus** (o protocolo da engenharia com o CLP A)
- **S7** (o protocolo do GET entre os CLPs)
- **TCP e IP** (a rede por baixo)
- **o ev e as regras** (o código)
- **fora da política** (ataque)
- **falha** (algo deixou de funcionar)
- **diferente, mas permitido**

Os avisos também têm cor: vermelho para **erro comum** e **atenção**, cinza para notas.

=== ideia: De onde vem cada coisa

- **O código do sensor** e as capturas da aula de diagnóstico: a base de tudo. Cada regra mostrada no site foi rodada nas capturas com o `conferir.py`.
- **O guia da aula de diagnóstico**: as resoluções dos casos 1 a 10 da aula.
- **O simulado** foi gerado para este site, com a mesma planta, os mesmos IPs e o mesmo ritmo da aula. Os quadros citados foram conferidos no tshark 4.6.

> **Atenção:** o simulado é **treino**. A prova tem outras capturas.
