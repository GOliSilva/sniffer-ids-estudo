# Módulo 05: O ev (3): cabeçalho e resposta

=== ideia: As 9 propriedades que faltam

:::chave
As últimas nove dizem se o **cabeçalho** confere e como a **resposta** se liga à pergunta. São elas que pegam o ataque em que o TCP e o IP estão perfeitos e **só a mensagem** está errada.
:::

| Propriedade | Em uma frase |
|---|---|
| `status` | o código de erro da resposta (0 = ok) |
| `transacao` | o número que liga a pergunta à resposta |
| `id_protocolo` | o identificador do protocolo no cabeçalho (Modbus 0, S7 `0x32`) |
| `unidade` | o Unit ID do Modbus |
| `tamanho` | o tamanho que o cabeçalho **diz** ter |
| `malformado` | `True` quando o cabeçalho não confere com o que chegou |
| `pareada` | `True` quando a resposta achou a pergunta dela |
| `tempo_resposta` | segundos entre a pergunta e a resposta |
| `bruto` | o payload TCP inteiro, em bytes |

No Wireshark, o cabeçalho Modbus é a seção **Modbus/TCP**: Transaction Identifier, Protocol Identifier, Length e Unit Identifier, nessa ordem, nos 7 primeiros bytes do payload.

![A seção Modbus/TCP de uma pergunta da linha de base: transação 4432, protocolo 0, tamanho 6, Unit ID 1](img/ws_modbus_pergunta.png)

=== ideia: ev.status

:::termo{nome="ev.status"}
O **código de erro** que veio na resposta. 0 quer dizer sem erro.
- **Só na resposta** na pergunta é sempre 0
- **Modbus** o *Exception Code* (`modbus.exception_code`) quando a função volta com `0x80` somado
- **S7, erro no cabeçalho** classe e código juntos num número de 16 bits (`s7comm.header.errcls` e `errcod`). Ex.: `0x8104`, a recusa de um S7-1200 sem PUT/GET liberado
- **S7, erro no item** o *Return code* do item quando não é `0xFF` (sucesso). Ex.: `0x0A`, objeto não existe
- **Na linha de base** sempre 0
:::

| `status` | Onde | O que quer dizer |
|---|---|---|
| 1 | Modbus | função ilegal: o servidor não tem essa função |
| 2 | Modbus | endereço ilegal: o registrador não existe |
| 3 | Modbus | valor ilegal (por exemplo, quantidade grande demais) |
| `0x8104` | S7 | o CLP recusou o serviço (S7-1200 sem PUT/GET) |
| `0x0A` | S7 | o item pedido não existe (DB que não existe) |

![Uma exceção Modbus (caso 2 da aula): a função volta como 0x83 e o Exception Code 2 vira ev.status](img/ws_modbus_excecao.png)

```python
# qualquer erro
ev.direcao == "resposta" and ev.status != 0

# endereço que não existe
ev.protocolo == "modbus" and ev.status == 2
```

> **Erro comum:** achar que `status != 0` já é ataque. No caso 2 da aula, a exceção 02 vinha da **configuração** errada da supervisão: sempre o mesmo endereço, a cada segundo, desde o início. O mesmo `status` numa **varredura** (endereço mudando a cada pedido) é sondagem.

=== ideia: ev.transacao

:::termo{nome="ev.transacao"}
O número que o cliente põe na pergunta e o servidor **repete** na resposta.
- **Modbus** *Transaction Identifier* (`mbtcp.trans_id`), os 2 primeiros bytes
- **S7** *PDU Reference* (`s7comm.header.pduref`)
- **Na linha de base** cresce de 1 em 1 a cada pergunta (Modbus a partir de 4432; S7 a partir de 1201)
:::

Para que serve:

- **Casar pergunta e resposta.** O sensor usa a transação para isso (é o que dá `pareada` e `tempo_resposta`).
- **Ver se é o mesmo programa.** Uma pergunta de um programa novo começa a contar de outro número; o programa de sempre segue a sequência.
- **Pegar retransmissão.** Um segmento TCP retransmitido chega de novo com a **mesma** transação.

```python
vistas = set()

def pergunta_repetida(ev):
    if ev.direcao != "pergunta":
        return False
    chave = (ev.protocolo, ev.origem, ev.transacao)
    repetida = chave in vistas
    vistas.add(chave)
    return repetida
```

=== ideia: ev.id_protocolo e ev.unidade

:::termo{nome="ev.id_protocolo"}
O identificador do protocolo no cabeçalho.
- **Modbus** *Protocol Identifier* (`mbtcp.prot_id`). No Modbus TCP é **sempre 0**
- **S7** o primeiro byte do cabeçalho S7. É **sempre `0x32`**
- **Qualquer outro valor** é mensagem montada errada, ou de propósito; o `ev` vem com `malformado=True`
:::

:::termo{nome="ev.unidade"}
O **Unit ID** do Modbus TCP (`mbtcp.unit_id`), o 7º byte.
- **Para que existe** endereçar um escravo atrás de um gateway Modbus TCP para RTU
- **No S7-1200** não é usado: o CLP responde a qualquer Unit ID
- **Na linha de base** 1. No S7, sempre 0
:::

![Unit ID 2 no caso 9 da aula: o CLP responde igual, porque o S7-1200 não usa o Unit ID](img/ws_unit_id.png)

> **Atenção:** Unit ID diferente **não quebra** nada nesta planta. O que decide a classe é o padrão: um valor novo e fixo depois de uma reconexão é configuração (caso 9 da aula); muitos valores em sequência, em poucos segundos, é alguém **procurando** escravos.

=== ideia: ev.tamanho e ev.malformado

:::termo{nome="ev.tamanho"}
O tamanho que o cabeçalho **diz** que a mensagem tem.
- **Modbus** o campo *Length* (`mbtcp.len`): conta os bytes **depois** dele (Unit ID + função + dados). Numa mensagem certa, `len(ev.bruto) == 6 + ev.tamanho`
- **S7** o tamanho do TPKT (`tpkt.length`): conta **tudo**. Numa mensagem certa, `len(ev.bruto) == ev.tamanho`
- **Na linha de base** Modbus 6 na pergunta e 23 na resposta; S7 31 na pergunta e 45 na resposta
:::

![O TPKT de uma pergunta S7: Length 31, o tamanho total da mensagem](img/ws_s7_tpkt.png)

:::termo{nome="ev.malformado"}
`True` quando o cabeçalho **não confere** com o que chegou.
- **Modbus** Protocol ID diferente de 0, ou `Length` que não bate com o tamanho do payload, ou payload curto demais (menos de 8 bytes)
- **S7** TPKT com tamanho errado, protocolo diferente de `0x32`, ou dados cortados
- **Na linha de base** sempre `False`
:::

Antes, o sensor da aula **jogava fora** essas mensagens. O da prova entrega o `ev` marcado, para a regra decidir:

```python
# qualquer cabeçalho estranho
ev.protocolo == "modbus" and ev.malformado

# só o Protocol ID
ev.protocolo == "modbus" and ev.id_protocolo != 0

# só o Length
ev.protocolo == "modbus" and len(ev.bruto) != 6 + ev.tamanho
```

> **Atenção:** num `ev` malformado, os outros campos foram lidos **como se** o cabeçalho estivesse certo. Confie neles com cuidado.

=== ideia: ev.pareada e ev.tempo_resposta

:::termo{nome="ev.pareada"}
`True` quando esta **resposta** achou a pergunta dela.
- **Como o sensor casa** pelo protocolo, pelo IP do cliente e pela transação
- **Na pergunta** sempre `False` (não se aplica)
- **Resposta sem par** quando ninguém fez aquela pergunta: a captura começou no meio de uma troca, a resposta chegou **duas vezes** (retransmissão), ou alguém **injetou** uma resposta
- **Na linha de base** toda resposta é pareada
:::

:::termo{nome="ev.tempo_resposta"}
Quantos **segundos** a resposta levou desde a pergunta.
- **Só na resposta pareada** nas outras, 0
- **No Wireshark** `modbus.response_time` (e o *Time from request* da resposta)
- **Na linha de base** Modbus de 0,003 a 0,007; S7 de 0,002 a 0,005
:::

Numa resposta pareada, o sensor também **copia da pergunta** o endereço e a quantidade (módulo 04). Por isso uma resposta **sem par** chega com `endereco=0` e `quantidade=0`.

```python
# resposta que ninguém pediu
ev.direcao == "resposta" and not ev.pareada

# resposta demorada
ev.pareada and ev.tempo_resposta > 0.050
```

> **Erro comum:** escrever `not ev.pareada` sem `ev.direcao == "resposta"`. Toda **pergunta** tem `pareada=False`, então a regra dispara em todas.

=== ideia: ev.bruto

:::termo{nome="ev.bruto"}
O **payload TCP inteiro**, exatamente como chegou.
- **Tipo** `bytes`. `ev.bruto[0]` é um número de 0 a 255; `ev.bruto[0:2]` são os 2 primeiros bytes
- **No Wireshark** o que fica destacado no painel de bytes quando você clica em Modbus/TCP + Modbus (ou TPKT + COTP + S7)
- **Para que serve** olhar qualquer coisa que o sensor **não decodifica**
:::

```python
# tamanho real (Modbus normal: pergunta 12, resposta 29)
len(ev.bruto)

# Modbus: o byte da função, com o 0x80 da exceção
ev.bruto[7]

# Modbus: a transação, lida à mão
int.from_bytes(ev.bruto[0:2], "big")

# S7: o texto do PLC Stop
b"P_PROGRAM" in ev.bruto
```

Posições no Modbus (o que o Wireshark mostra em Modbus/TCP e Modbus):

| Bytes | Campo |
|---|---|
| `bruto[0:2]` | Transaction ID |
| `bruto[2:4]` | Protocol ID |
| `bruto[4:6]` | Length |
| `bruto[6]` | Unit ID |
| `bruto[7]` | função (+ `0x80` se for exceção) |
| `bruto[8:]` | dados: endereço e quantidade na pergunta; nº de bytes e valores na resposta |

=== questao: Questão: a recusa

### ✍️ Questão de prova Treino M05 Q1: o CLP recusou

No caso 3 da aula, um IP de fora tenta ler o CLP A por S7 e recebe `0x8104`. Escreva uma regra que pega **a recusa**, sem olhar o IP.

=== resolucao: Resolução

?? Em que mensagem está a recusa?

Na **resposta** S7 do CLP A. É o erro no cabeçalho: classe `0x81`, código `0x04`.

?? Que propriedade guarda isso?

`ev.status`, que no S7 junta classe e código em um número: `0x8104`.

?? A regra dispara na linha de base?

Não: na base todo `status` é 0.

?? Como fica?

```python
def s7_recusado(ev):
    return ev.protocolo == "s7" and ev.direcao == "resposta" and ev.status == 0x8104
```

> **Erro comum:** escrever `ev.status == 8104`. É hexadecimal: `0x8104` vale 33028 em decimal.

=== treino: Treino M05 Q2

### ✍️ Questão de prova Treino M05 Q2: lendo o bruto

O `ev.bruto` de uma pergunta Modbus é `11 50 00 00 00 06 02 03 00 00 00 0a`. Diga `transacao`, `id_protocolo`, `tamanho`, `unidade`, `funcao`, `endereco` e `quantidade`, e se é `malformado`.

??? resposta

`transacao` = `0x1150` = 4432; `id_protocolo` = 0; `tamanho` = 6; `unidade` = **2**; `funcao` = 3; `endereco` = 0; `quantidade` = 10. Não é malformado: 12 bytes = 6 + 6. A diferença da base é só o Unit ID 2.

=== treino: Treino M05 Q3

### ✍️ Questão de prova Treino M05 Q3: pareada ou não?

Diga o `pareada` de cada `ev`:

1. A pergunta Modbus de transação 4432.
2. A resposta de transação 4432, logo depois.
3. Uma segunda resposta de transação 4432, chegando de novo 300 ms depois.

??? resposta

1. `False`: é pergunta.
2. `True`: casou com a pergunta 4432.
3. `False`: a pergunta já foi usada pela primeira resposta. É o sinal de uma resposta **duplicada** (retransmissão) ou **injetada**.

=== resumo: Para levar

1. **ev.status:** erro da resposta. Modbus 1, 2, 3; S7 `0x8104` (recusa), `0x0A` (não existe).
2. **ev.transacao:** liga pergunta e resposta; cresce de 1 em 1; repetida = retransmissão.
3. **ev.id_protocolo:** Modbus 0, S7 `0x32`. **ev.unidade:** Unit ID, 1 na base, ignorado pelo S7-1200.
4. **ev.tamanho e ev.malformado:** o cabeçalho diz um tamanho; se não bate, `malformado=True`.
5. **ev.pareada e ev.tempo_resposta:** só na resposta. Sem par = ninguém perguntou.
6. **ev.bruto:** o payload inteiro, para o que o sensor não decodifica.
