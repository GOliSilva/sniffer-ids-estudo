# Módulo 10: Ataques no payload

=== ideia: TCP perfeito, mensagem errada

:::chave
Num ataque de payload, **Ethernet, IP e TCP estão perfeitos**: os IPs de sempre, a conexão de sempre, nenhum aviso no Expert Info. Só a **mensagem** Modbus ou S7 tem algo diferente. Os passos 1 e 2 do método não acham nada.
:::

Onde o ataque pode estar, e que propriedade do `ev` o mostra:

| Onde | O que muda | No `ev` |
|---|---|---|
| o **valor** escrito | um número fora da faixa do processo | `valores` na pergunta de escrita |
| o **valor** lido | um número que nunca aparece na planta | `valores` na resposta |
| o **cabeçalho** | Protocol ID, Length, Unit ID | `id_protocolo`, `tamanho`, `malformado`, `unidade` |
| a **função** | uma função que a planta não usa | `funcao`, `operacao == "outra"` |
| o **endereço** | registradores fora do mapa, em sequência | `endereco`, `quantidade` |
| o **casamento** | resposta sem pergunta, transação fora da sequência | `pareada`, `transacao` |

Para cada um, este módulo dá o filtro do Wireshark, a regra modelo e como classificar.

=== ideia: Valor fora da faixa na escrita

:::chave
Alguém de dentro (a própria engenharia, ou um programa nela) **escreve** um valor que o processo não aceita. A política deixa a engenharia escrever, mas não **aquele valor**.
:::

- **Wireshark:** `modbus.func_code == 6 || modbus.func_code == 16`; abra a pergunta e veja *Register Value*.
- **Antes de julgar:** consulte o **mapa** (módulo 01). Sem mapa, compare com a linha de base e com escritas anteriores.

```python
def escrita_fora_da_faixa(ev):
    return (ev.protocolo == "modbus" and ev.direcao == "pergunta"
            and ev.operacao == "escrita" and ev.endereco == 2
            and any(v > 400 for v in ev.valores))
```

**Classe:** fora da política (valor proibido). A hora ajuda: de madrugada, sem ordem de serviço, pesa para ataque. Dentro da faixa, no expediente, é **diferente, mas permitido**.

> **Erro comum:** escrever só `any(v > 400 ...)` sem `ev.endereco == 2`. HR0 é temperatura e passa de 400 sem problema nenhum. A faixa é **por registrador**.

=== ideia: Valor estranho na leitura

:::chave
A **resposta** traz um valor que a planta nunca mostrou, e **ninguém escreveu**. Ou o instrumento falhou, ou alguém está falsificando a resposta.
:::

- **Wireshark:** `modbus.regval_uint16 == 32767` (ou outro valor), *Apply as Column* em `modbus.regval_uint16` para ver a série.
- **Valores típicos de falha:** `32767` (`0x7FFF`) é o estouro de uma entrada analógica no S7-1200 (fio rompido, sensor fora da faixa). `0` ou `65535` parados também são suspeitos.

```python
def temperatura_estranha(ev):
    return (ev.protocolo == "modbus" and ev.direcao == "resposta"
            and ev.endereco == 0 and ev.valores and not 200 <= ev.valores[0] <= 300)
```

**Classe:** depende de **quem**. Se nada mais mudou (mesma conexão, nenhuma escrita, respostas pareadas, no tempo de sempre), é **falha do instrumento**: a rede está saudável, o dado está errado. Se as respostas vêm **sem par** ou com outro padrão, alguém pode estar injetando.

=== ideia: Resposta sem pergunta

:::chave
Chega ao cliente uma resposta com uma **transação que ninguém pediu**. No TCP está tudo certo; só o casamento pergunta-resposta denuncia.
:::

- **Wireshark:** `modbus && ip.src == 192.168.0.11 && !modbus.request_frame` (resposta para a qual o Wireshark não achou pergunta).
- **No `ev`:** `pareada == False` numa resposta; o `endereco` e a `quantidade` chegam 0 (não havia pergunta para copiar).

```python
def resposta_sem_pergunta(ev):
    return ev.protocolo == "modbus" and ev.direcao == "resposta" and not ev.pareada
```

**Classe:** fora da política (injeção de resposta falsa), quando a transação está fora da sequência e os valores são diferentes dos que a planta mostra. Mas confira dois casos inocentes:

- a captura começou **entre** uma pergunta e a resposta: só a **primeira** resposta fica sem par;
- uma resposta **retransmitida** chega duas vezes: a segunda não tem par, mas tem a **mesma** transação da anterior e o Expert Info acusa retransmissão.

=== ideia: Cabeçalho adulterado

:::chave
O cabeçalho MBAP traz um **Protocol ID** diferente de 0, um **Length** que não bate ou um **Unit ID** estranho. Nenhum cliente Modbus de verdade faz isso por acaso.
:::

- **Wireshark:** `mbtcp.prot_id != 0` (o Expert Info mostra *Invalid protocol ID*); `mbtcp.unit_id != 1`; para o Length, compare `mbtcp.len` com `tcp.len - 6`.
- **No `ev`:** `id_protocolo`, `tamanho`, `unidade`, `malformado`.

```python
def cabecalho_errado(ev):
    return ev.protocolo == "modbus" and ev.malformado

def unit_id_varrendo(ev):
    return ev.protocolo == "modbus" and ev.direcao == "pergunta" and ev.unidade != 1
```

O servidor costuma **não responder** uma mensagem com cabeçalho inválido: no Wireshark aparece só o ACK do TCP.

**Classe:** fora da política (mensagem forjada, teste de robustez). Para o Unit ID, olhe o padrão: **um** valor novo e fixo é configuração (caso 9 da aula); **muitos** valores em sequência rápida é alguém procurando escravos atrás de um gateway.

=== ideia: Função que a planta não usa

:::chave
A planta só usa leitura (3) e, às vezes, escrita (6, 16). Uma função diferente é alguém **perguntando o que o equipamento sabe fazer**.
:::

| Função | O que pede | Por que preocupa |
|---|---|---|
| 43, MEI 14 | *Read Device Identification*: fabricante, modelo, versão | é o primeiro passo para achar uma vulnerabilidade daquele modelo |
| 8 | *Diagnostics* | algumas subfunções reiniciam a comunicação ou deixam o escravo só ouvindo |
| 17 | *Report Server ID* | identificação, como a 43 |
| 90 e outras | funções de fabricante | ferramentas de programação |

- **Wireshark:** `modbus.func_code != 3` (e `!= 6`, `!= 16` se a escrita for normal na planta).
- **Resposta típica:** exceção **01** (função ilegal), quando o servidor não tem a função.

```python
def funcao_estranha(ev):
    return (ev.protocolo == "modbus" and ev.direcao == "pergunta"
            and ev.operacao == "outra" and not ev.malformado)
```

O `not ev.malformado` evita somar aqui uma mensagem de cabeçalho quebrado, cuja "função" é lixo.

**Classe:** fora da política (sondagem).

=== ideia: Varredura de endereços

:::chave
Muitos pedidos seguidos, cada um num **endereço** diferente, muito mais rápido que o ritmo da planta. A maioria volta com **exceção 02**: o atacante está desenhando o mapa de memória.
:::

- **Wireshark:** `modbus.exception_code == 2`; *Apply as Column* em `modbus.reference_num` mostra os endereços subindo.
- **Contraste:** o caso 2 da aula tem a mesma exceção 02, mas **sempre no mesmo endereço**, uma vez por segundo, desde o início: configuração.

```python
def fora_do_mapa(ev):
    return (ev.protocolo == "modbus" and ev.direcao == "pergunta"
            and ev.operacao == "leitura" and ev.endereco + ev.quantidade > 10)
```

Para separar varredura de configuração **na regra**, use memória (módulo 06): conte quantos endereços diferentes apareceram.

**Classe:** fora da política (sondagem).

=== ideia: Tempo: quando o payload está certo mas atrasado

:::chave
Nem toda diferença está nos bytes. Uma resposta **certa** que chega **tarde** aparece só no `tempo_resposta`.
:::

- **Wireshark:** `modbus.response_time > 0.05`; no I/O Graph, a linha de `modbus.response_time` (eixo Y em *MAX*).
- **No `ev`:** `pareada and tempo_resposta > limite`. Escolha o limite **acima** do maior da base (7 ms), com folga.

```python
def resposta_lenta(ev):
    return ev.direcao == "resposta" and ev.pareada and ev.tempo_resposta > 0.050
```

**Classe:** em geral **falha da aplicação** (o CLP está demorando: ciclo de varredura alto, sobrecarga). Se ao mesmo tempo aparece muito tráfego novo contra o CLP, pode ser ataque de negação de serviço.

=== questao: Questão: qual regra?

### ✍️ Questão de prova Treino M10 Q1: escolha a propriedade

Para cada ataque, diga a propriedade do `ev` que o mostra e escreva a condição:

1. Pedidos com Length 255 em mensagens de 12 bytes.
2. Uma pergunta com função 8.
3. Resposta com transação 9 quando a sequência está em 5000.

=== resolucao: Resolução

?? Em que parte da mensagem está cada um?

1 no cabeçalho (Length); 2 na função; 3 no casamento.

?? Que propriedade guarda cada parte?

1. `ev.tamanho` (e `ev.malformado`, porque 12 ≠ 6 + 255).
2. `ev.funcao` (8 cai em `operacao == "outra"`).
3. `ev.pareada` (ninguém perguntou a transação 9) e `ev.transacao`.

?? Como ficam as condições?

```python
# 1
ev.protocolo == "modbus" and ev.malformado

# 2
ev.protocolo == "modbus" and ev.direcao == "pergunta" and ev.funcao == 8

# 3
ev.protocolo == "modbus" and ev.direcao == "resposta" and not ev.pareada
```

=== treino: Treino M10 Q2

### ✍️ Questão de prova Treino M10 Q2: falha ou ataque?

A partir dos 40 s, o HR0 lido passa a valer sempre 0. Ninguém escreveu, as respostas são pareadas e chegam em 5 ms, a conexão é a de sempre. Classifique.

??? resposta

**Falha do instrumento**, não da rede: nada mudou no **quem** (mesma conexão, mesmo programa), as respostas casam com as perguntas, no tempo de sempre, e não houve escrita. O dado está errado na origem. A regra pega pelo valor (`ev.valores[0] == 0` na resposta de HR0), e a classe vem do resto estar normal.

=== treino: Treino M10 Q3

### ✍️ Questão de prova Treino M10 Q3: varredura de Unit ID

Em 3 s, a `.29` faz 60 perguntas com Unit ID de 2 a 61, e o CLP responde todas. Por que isso é fora da política, se no caso 9 da aula o Unit ID 2 era permitido?

??? resposta

Pelo **quantas vezes**: no caso 9, **um** valor novo, fixo, depois de uma reconexão (configuração). Aqui, **60** valores em sequência rápida: alguém procurando quais escravos respondem atrás de um gateway. É sondagem.

=== resumo: Para levar

1. **Payload:** TCP e IP perfeitos; a diferença está na mensagem. Os passos 3, 4 e 5 do método é que acham.
2. **Valor:** faixa **por registrador**, na pergunta de escrita ou na resposta de leitura.
3. **Cabeçalho:** `id_protocolo != 0`, `malformado`, `unidade`. O servidor costuma só dar ACK.
4. **Função:** `operacao == "outra"` (43, 8, 17). Resposta típica: exceção 01.
5. **Casamento:** `not ev.pareada` numa resposta. Descarte primeira resposta e retransmissão.
6. **Varredura:** endereço ou Unit ID mudando rápido. Mesma exceção, padrão diferente da configuração.
